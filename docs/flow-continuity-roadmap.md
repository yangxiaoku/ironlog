# Ironlog 操作连贯性打磨路线图（Flow Continuity Polish）

> 从真实健身房使用者视角走完「进房开练 → 训中记录 → 组间微操 → 补录历史 → 完赛复盘」全链路，消除交互断层、误触退回与多余跳转。

## 7 项核心连贯性修复

### 1. 开练控制台草稿优先 + 一键直达开练
- **现状痛点**：已有进行中的训练（云端草稿或本机草稿）时，`WorkoutView` 顶部控制台仍显示「开始今日计划」，点击后触发覆盖警告；同时每次从计划或模板开练都必须先跳 `RoutinePreviewModal` 再点一次「开始训练」。
- **改造方案**：
  - 抽取 `launchRoutineDirectly` 公共方法（支持 `plan` / `template` / `scheduled`，自动应用减载缩放与 `autoWarmup` 热身组），点击今日计划主按钮或快捷训练日标签时**一键直达训练编辑器**，旁边保留轻量的「预览目标」按钮供需要提前调整时使用。
  - 检测到进行中训练或本机草稿时，顶部控制台主卡自动切换为**「继续进行中的训练（已练 X/Y 组）」**，不再与今日计划按钮打架，同时消除下方重复草稿卡片。

### 2. 训中子浮层接入手机返回手势 / ESC 拦截（防误关整场训练）
- **现状痛点**：`WorkoutEditorModal` 内的「训练设置」「最近历史」「肌群进度」「问教练」「合并训练日」「结束确认」为组件内部遮罩，未纳入 `ModalHost` 历史栈。手机侧滑返回或按 ESC 会直接关闭整个训练弹窗而非仅关闭当前子浮层。
- **改造方案**：
  - 在 `useUiStore` 中新增 `innerOverlayDismiss: (() => void) | null` 与 `setInnerOverlayDismiss`；`ModalHost` 像 `nestedConfirm` 一样为活跃子浮层压入独立 `ironlogInnerOverlay` history 记录，并在 `popstate` / `onCancel` / 顶部关闭按钮时**优先只关闭子浮层**，稳稳停留在训练页内。
  - 同步修复训中「历史」抽屉调用路径为后端真实路由 `/api/web/exercise-history/:exerciseId`。

### 3. 自由训练空态一键快选最近常练动作
- **现状痛点**：点击「自由训练」进入空态只看到「还没有动作 + 添加动作按钮」，必须多跳一次选动作弹窗。
- **改造方案**：
  - 在空态直接并行拉取 `/api/web/trained-exercises`（前 8 个最近常练动作），铺出快捷点选芯片，点一下立刻加入并进入第 1 组录入；下方保留「浏览全部动作库」主按钮。

### 4. 补录历史日期自动进入「快速补录模式」
- **现状痛点**：从日历选昨天补录训练时，顶栏秒表在走、勾完一组仍触发 90s 组间倒计时、单动作翻页且开启屏幕常亮。
- **改造方案**：
  - 当 `!isHistoricalEdit && date < todayStr` 时自动识别为 `isBackfillMode`：初始计时器暂停（`runningSince: null`）、默认以 `"all"` 全览视图展开、禁止自动触发组间休息倒计时与防息屏，并在顶部提示「历史补录模式 · 已关闭秒表与休息倒计时，保存时可填总时长」。

### 5. 组号菜单自动收起 + PR 突破自动切动作缓冲
- **现状痛点**：
  - 点击组号展开 `.set-action-menu` 后，点选组别或休息时长菜单仍挂在屏幕上占空间，输入重量或切动作时也不会收起。
  - 完成某动作最后一组若触发 `🏆 PR`，`320ms` 自动跳下一动作过快，来不及看到破纪录反馈。
- **改造方案**：
  - 点选组别、复制、加递减/休停或组后休息后自动收起菜单；聚焦任意输入框或切换动作时自动关闭打开的组菜单。
  - 触发 PR 时将完组自动跳转延迟延长至 `1300ms`（常规仍为 `320ms`），给足视觉反馈停留时间。

### 6. 动作百科「加入当前进行中训练」顺滑衔接
- **现状痛点**：在动作详情弹窗（尤其是训中点动作标题看百科时）只有「以此动作开始训练」，会把当前正在进行的训练覆盖掉。
- **改造方案**：
  - 当 `WorkoutEditorModal` 已在栈底打开时，在 `ExerciseDetailModal` 隐藏会覆盖草稿的「以此动作开始训练」或改为「返回当前训练」，避免训中看百科误点重置整场训练。

### 7. 完赛复盘页主次按钮重排 + 计划同步提醒卡片
- **现状痛点**：刚练完自动弹出 `WorkoutReportModal`，最醒目的主按钮却是「再练一次」，底部一口气平铺 8 个次要按钮，「同步回计划」淹没在按钮海里。
- **改造方案**：
  - `openWorkoutReport` 新增 `justCompleted?: boolean` 标记；刚完赛进入时，底部主按钮为**「完成并返回」** + 次要主操作**「分享战报」**，「再练一次」归入次要操作。
  - 当 `report.canSyncToActivePlan` 为真时，在操作区上方展示独立的轻量提醒条（**「本次训练与当前计划关联，可将最新动作与组数同步回计划」** + 一键同步按钮）。
  - 将低频工具按钮（存为模板、导出 `.fit`、复制摘要、编辑、删除）收纳至可展开的「更多操作」折叠组，保持完赛画面清爽克制。
